# v0.2 MVP Summary

## What changed

v0.2 turns phoenix-feed from a compiling skeleton into a local end-to-end MVP. The ingester writes source polls, active incident snapshots, unit history intervals, and lifecycle events. The API serves active incidents, incident detail, source-aware health, and a paid-history placeholder. The canary now checks the Phoenix Fire ArcGIS contract and writes `contract_canary`; the janitor drops old `raw` JSONB after `RAW_RETENTION`; `web/index.html` provides a static Leaflet map/list client.

## Deferred

Auth, billing, paid history search, notifications, geofences, scanner+Whisper ingestion, cold archive partitions, production alert integrations, deployment automation, and mobile app work remain out of scope for v0.2.

## Decisions made under autonomy

1. Kept the owner-requested OpenSpec path `openspec/changes/v0.2-mvp-complete/` even though OpenSpec 1.2.0 rejects dots for `status`; `openspec validate v0.2-mvp-complete` works and the proposal documents the exception.
2. Used `since` and `until` RFC3339 params for active endpoint time windows against `incident_date`.
3. Used `lat`, `lon`, and `radius_meters` for radius filtering, and rejected mixed `bbox` plus radius requests with `400`.
4. Treated first-run canary feature-count baseline absence as a note, not a failure, so a clean install can pass contract checks.
5. Left `/v1/incidents/history` as a hard `402` placeholder even if `PAID_TIER_ENABLED=true`; auth and paid search are intentionally deferred.

## Operational notes

The API fails `/v1/health` with `503` when the configured source has no successful poll or the latest success is older than 10 minutes. Incident unit history is observational: interval timestamps mean "first/last poll where we observed this status," not official dispatch times. The static web client expects the API at `http://localhost:8080` and relies on CORS headers added in v0.2.
