# v0.3 Deploy Summary

## What changed

v0.3 makes phoenix-feed deployable on a single DigitalOcean droplet and ready for Cactus Alert's freemium model. It adds optional API key auth, manual key generation, server-enforced detail/manual refresh cadences, Cactus-facing metadata in active and refresh responses, dev/prod Docker Compose files, per-binary Dockerfiles, Caddy TLS proxying, smoke scripts, cloud-init bootstrap, and a deployment runbook.

## Deferred

Billing, Stripe, app-store receipt validation, Redis-backed distributed rate limits, managed Postgres, multi-replica API deployment, Terraform, scanner+Whisper, notifications, geofences, paid history search, and production alert integrations remain deferred.

## Decisions made under autonomy

1. Kept `openspec/changes/v0.3-do-deploy/` exactly as requested, scaffolded manually because OpenSpec 1.2.0 rejects dotted names for some commands.
2. Used SHA-256 hex hashes for API keys and printed plaintext only from `cmd/keygen`.
3. Resolved anonymous client identity from `X-Client-ID`, then `X-Forwarded-For`, then `RemoteAddr`.
4. Used in-memory token buckets for v0.3 because the deployment is one API process; Redis is documented as the scale path.
5. Used Caddy instead of Traefik because the config is smaller for a manual DigitalOcean runbook.
6. Added `SMOKE_EXTERNAL=1` so the same Bash smoke script can verify a deployed URL without starting local Docker.

## Operational notes

Cached active-feed reads are repeatable so mobile clients can reopen reliably; detail reads still use the incident-read limiter and manual refresh uses 120 seconds while reading cache only. `/v1/health` bypasses incident read rate limits. Production schema setup applies `db/schema.sql` first and then every `db/migrations/*.sql`.
