# Design

## Landing Restoration

The legacy coming-soon page remains the structural and visual source of truth. The implementation will copy its layout, CSS approach, footer structure, app-store badges, phone mockup composition, and cream/light palette into `web/landing/`, then apply only the requested Cactus Watch rebrand and copy changes.

The production Caddy CSP only allows same-origin assets and inline styles. The restored page therefore uses local CSS/images only and must not include Tailwind CDN, Google Fonts, font CDNs, JavaScript CDNs, analytics snippets, or third-party scripts.

## Sub-page Chrome

Privacy, terms, about, and FAQ pages keep their body content exactly as it exists today. Their surrounding page chrome changes to the same legacy-style header, navigation, cream background, typography, and footer so the site reads as one product.

## Hero Assets

Dan's three supplied screenshots are copied from the read-only `abusedDRS` source folder into `web/landing/img/` with URL-safe names. Each image receives a resized PNG and a WebP sibling generated by Pillow with `quality=78` and `method=6`, targeting a long side between 720 and 900 pixels so the PNG fallback is substantially smaller than the raw sources.

## Active-Window Retention

The active-feed rule must distinguish incident dispatch age from source observation recency. If the latest poll still observes an incident, it remains active; only incidents that have stopped appearing in source data are eligible for age-out by the cleared/not-seen retention window.

The investigation will grep both repositories for `kIncidentMaxAgeMinutes` and `kClearedIncidentMaxAgeSeconds`, then read the phoenix-feed ingester, janitor, and active query path before changing behavior. The backend test will model an incident dispatched about 2 hours ago but last observed in the latest poll and assert it remains included.

## Risks

The largest landing risk is accidentally altering legal/about/FAQ body copy while changing chrome. This will be mitigated by extracting and comparing the body content before and after the rewrite.

The largest backend risk is broadening the active feed to include stale incidents. The fix is constrained to incidents still observed recently; incidents no longer seen continue to expire by the existing cleared/not-seen retention rule.
